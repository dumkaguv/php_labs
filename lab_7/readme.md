# Лабораторная работа 7. Шаблонизация

## Как запустить

```bash
php composer.phar install
php -S localhost:8000
```

Открыть в браузере:

- `http://localhost:8000/index.php` - вариант с нативными PHP-шаблонами.
- `http://localhost:8000/twig.php` - вариант с Twig.

## Структура проекта

- `src/functions.php` - функции для валидации, работы с JSON, сортировки и форматирования.
- `src/handler.php` - обработка запроса и подготовка данных для шаблонов.
- `templates/php/` - нативные PHP-шаблоны.
- `templates/twig/` - шаблоны Twig.
- `index.php` - страница с PHP-шаблонами.
- `twig.php` - страница с Twig-шаблонами.
- `data.json` - файл с сохраненными записями дневника.

## Что реализовано

Проект разделен на два слоя:

- логика находится в `src/`;
- представление находится в `templates/`.

В проекте есть два варианта отображения одной и той же функциональности:

- через обычные PHP-шаблоны;
- через шаблонизатор Twig.

В Twig используется наследование шаблонов:

```twig
{% extends 'layout.html.twig' %}
{% block content %}{% endblock %}
```

Также подключены отдельные шаблоны формы и списка:

```twig
{% include 'form.html.twig' %}
{% include 'list.html.twig' %}
```

## Дополнительное задание

В проекте зарегистрирован собственный фильтр Twig:

```twig
{{ record.sleep_hours|format_sleep }}
```

Он форматирует количество часов сна в понятный вид, например `8 h`.

## Контрольные вопросы

### 1. В чем отличие нативных PHP-шаблонов от Twig?

Нативные PHP-шаблоны - это обычные `.php` файлы, где HTML смешивается с небольшими PHP-вставками. Такой подход простой и не требует дополнительных библиотек.

Twig - это отдельный шаблонизатор со своим синтаксисом. Он поддерживает автоэкранирование, наследование шаблонов, блоки, фильтры и подключение частей шаблона.

Плюс PHP-шаблонов - простота. Минус - легко случайно смешать вывод HTML с логикой обработки данных.

Плюс Twig - более чистые и безопасные шаблоны. Минус - нужна установка через Composer и дополнительная зависимость.

### 2. Зачем разделять логику и представление?

Логика должна обрабатывать запросы, проверять данные, читать и записывать файлы, сортировать записи и подготавливать переменные.

Представление должно только отображать уже готовые данные.

Если смешивать все в одном файле, проект становится сложнее читать и изменять. Например, при изменении HTML можно случайно сломать обработку формы, а при изменении логики - повредить вывод страницы.

### 3. Что такое наследование шаблонов в Twig?

Наследование шаблонов позволяет создать один общий макет страницы, например с `header`, навигацией и общей структурой HTML.

Команда:

```twig
{% extends 'layout.html.twig' %}
```

означает, что текущий шаблон использует общий макет.

Блок:

```twig
{% block content %}{% endblock %}
```

обозначает место, куда дочерний шаблон вставляет свой HTML-код.
